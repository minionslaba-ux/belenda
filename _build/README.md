# Сборка сайта

Сайт — обычные статические HTML-страницы, которые GitHub Pages отдаёт как есть:

| Адрес | Страница |
|---|---|
| `/` | главная |
| `/about/` | о компании |
| `/catalog/`, `/catalog/<раздел>/` | каталог и разделы |
| `/products/<slug>/` | карточка товара |
| `/contacts/`, `/privacy/` | контакты, политика |
| `/kk/…`, `/en/…` | то же на казахском и английском |

Страницы генерируются из `_build/source.html` — выгрузки конструктора, где лежат
шаблон, тексты, товары и переводы. Папки с `_` в начале GitHub Pages не публикует.

## Как пересобрать

```bash
python3 _build/build.py
```

Нужны Python 3 и Node.js с Playwright (Chromium). Сборка занимает около 10 минут:
каждая страница прорисовывается в браузере и сохраняется готовым HTML.

Что делает `build.py`:
1. дорабатывает шаблон из `source.html`: настоящие ссылки вместо переходов по `#/…`,
   `data-*`-атрибуты для `site.js`;
2. выкладывает картинки и шрифты из выгрузки в `assets/b/`;
3. `prerender.js` открывает каждую страницу на ru/kk/en и снимает готовую разметку,
   а также фрагменты, которые появляются по клику (меню, окно заявки, cookie-баннер,
   подсказки поиска, таблица каталога);
4. собирает `index.html` для каждой страницы с мета-тегами, hreflang и schema.org,
   общий `assets/site.css`, `sitemap.xml`, `robots.txt`, поисковые индексы
   `assets/search-*.json`.

## Интерактив

`_build/site.js` → `/assets/site.js`: фон с лентами, след курсора, видеоплеер,
карта, анимации, меню, окно заявки, формы, cookie, поиск с подсказками,
фильтр и таблица в каталоге, переадресация старых ссылок вида `/#/product/1`.

Наверху `site.js` — `GA_ID` и `YM_ID` для Google Analytics и Яндекс.Метрики
(загружаются только после согласия на cookie) и адрес приёма заявок `LEAD_URL`.
